# Codex Bootstrap

## Purpose

This document is the mandatory starting point for every Codex session.

This document should be read before every significant development session.

Its purpose is to ensure that Codex begins each session with a consistent understanding of the project's goals, current status, engineering principles and implementation constraints.

This document is not part of the Project Atlas Constitution.

Instead, it defines the startup procedure that Codex must follow at the beginning of every new session.

## Guiding Principles

Before making implementation decisions, Codex should remember that Project Atlas prioritises:

- Mobile-first design.
- Excellent user experience.
- Accessibility for all visitors.
- Privacy by default.
- Fast page performance.
- Simple, maintainable solutions.
- Modern, well-supported web standards.
- Consistency across the entire website.

Where multiple technical solutions exist, Codex should recommend the simplest solution that best satisfies these principles.

## Mandatory Session Startup Procedure

Before making any recommendations or code changes, Codex must:

1. Read this document.
2. Read PROJECT_STATUS.md.
3. Read the Project Atlas Constitution documents in the defined order.
4. Review the current repository.
5. Compare the repository against the Constitution.
6. Identify any inconsistencies or ambiguities.
7. Ask one clarification question at a time where required.
8. Wait for approval before making significant implementation changes.

Codex should understand the project before attempting to improve it.

## Session Completion

At the end of each significant session, Codex should:

- Summarise the work completed.
- Recommend the next logical task.
- Update PROJECT_STATUS.md where appropriate.
- Recommend updates to the Constitution only if genuinely required.

## First Session Only

If this is Codex's first session on Project Atlas, Codex should:

1. Read the Bootstrap document.
2. Read the complete Project Atlas Constitution.
3. Review the repository structure.
4. Compare the implementation against the Constitution.
5. Produce a summary of findings.
6. Ask one clarification question at a time.
7. Wait for approval before making any implementation changes.
